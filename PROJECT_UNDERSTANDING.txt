WHAT IT IS
----------
Class Timer Pro is a Flutter app (package name "class_timer", v1.0.0+5) that
functions as an offline-first academic scheduling assistant for students. It
goes beyond a plain timetable/reminder app by combining:
  - Multiple ways to get a timetable into the app (manual entry, Excel import,
    matrix/grid-style OCR import from photos)
  - Conflict detection between classes/study sessions
  - Notifications with "smart buffer" contextual reminders
  - A Focus Mode for study sessions
  - Gamified productivity tracking (streaks, coins, streak freezes)
  - Academic tools: grade calculator, absence tracker, study planner,
    performance stats, course/program management, timetable explorer

The README.md and logic_and_algorithm.txt describe an ambitious full vision
(AI OCR from photos/PDFs, Google Calendar two-way sync, predictive scheduling
etc.) — these read as a product spec / roadmap. The actual codebase implements
a meaningful subset of this, described below.

TECH STACK
----------
- Flutter, Dart SDK ^3.11.0
- State/data: Provider (declared, though most screens use direct
  StatefulWidget + service calls rather than heavy Provider usage)
- Local storage: Hive + hive_flutter (offline-first persistence), with
  hive_generator/build_runner for generated adapters (*.g.dart files)
- Excel import: `excel` package + `file_picker`
- OCR: `google_mlkit_text_recognition` + `image_picker` (for photographed/
  screenshotted timetables — "matrix" grid parsing, not general PDF/AI OCR)
- Notifications: `awesome_notifications` + `timezone`
- Calendar: `device_calendar` (native device calendar sync)
- Location: `geolocator` (used for a "proximity to campus" late-trigger
  feature, checked periodically from main.dart)
- Audio: `just_audio` (focus mode ambient/focus sounds)
- Theming: `google_fonts`, `flutter_svg`, custom AppTheme with light/dark mode
- Icons: `flutter_launcher_icons` configured against assets/logo.png

KEY OBSERVATIONS / ARCHITECTURE NOTES
--------------------------------------
- There are two coexisting model/architecture styles: a simpler
  lib/models + lib/services structure (most of the app) and a small
  clean-architecture-flavored lib/data + lib/domain slice specifically for
  the Excel "matrix" timetable import (event_model, student_profile_model,
  import_matrix_timetable use case). This suggests the matrix-import feature
  was built/refactored more recently or by a different pass than the rest.
- Conflict detection is split across three files (conflict_engine,
  conflict_crusher, conflict_service) — worth checking for overlap/duplication
  if working in this area.
- main.dart is doing double duty as both app bootstrap/routing AND the full
  DashboardScreen implementation (over 1000 lines) — a candidate for
  extraction into lib/screens/home_screen.dart-style organization (note:
  lib/screens/home_screen.dart already exists separately, so DashboardScreen
  in main.dart may be legacy/duplicate — worth clarifying before editing).
- Gamification (coins, streaks, streak freezes, milestone badges at 3/7/30/100
  days) is a fully implemented feature, not just in the roadmap — tracked via
  UserProductivity (Hive model) and LocalStorageService.
- Crisis Mode (exam week) is a toggle in the drawer, persisted via
  LocalStorageService.isCrisisMode()/setCrisisMode() — implies some downstream
  behavior (likely more aggressive study reminders) elsewhere in the app.
- Routing is a manual onGenerateRoute switch (no go_router/named nav package),
  with custom transition helpers per route.
- Global error handling is set up in main() (FlutterError.onError and
  PlatformDispatcher.onError) with a fallback error Scaffold if startup fails.

CURRENT STATE VS. THE README ROADMAP
--------------------------------------
Implemented: Excel/matrix import, OCR-based grid parsing (ML Kit), manual
class entry, conflict detection + rescheduling suggestions, local
notifications with buffer-style reminders, Focus Mode with sound, device

Per the README's "Version Roadmap," this app looks to be somewhere around
v1.5–v2.0 in ambition (Excel import + conflict detection done; some AI/OCR

KNOWN ISSUES (verified 2026-08-26 via flutter analyze/test + code reading)
----------------------------------------------------------------------------
`flutter analyze` is clean. Issues found by actually reading service
implementations and their call sites, not just the docs.

FIXED on 2026-08-26 (flutter analyze clean, all 7 tests pass):
1. "Wipe everything" now actually clears all boxes.
   lib/services/local_storage_service.dart clearAllData() now also clears
   courseBox, programBox, productivityBox, and attendanceBox (previously
   only classBox/studyBox/settingsBox).
2. Streak milestone bonus coins (+10 @ 7-day streak, +50 @ 30-day streak) no
   longer lost on restart. updateStreak() now applies the milestone bonus to
   stats.coins BEFORE the single productivityBox.put('stats', stats) call.
3. Attendance record key collisions fixed. markAttendance() now zero-pads
   month/day in the storage key, so e.g. Jan 15 and Nov 5 no longer collide.
   Note: any attendance rows written under the old unpadded keys before this
   fix are orphaned under their old keys (no migration was run).
4. Conflict detection now runs on manual add/edit, not just import.
   lib/screens/edit_event_screen.dart _save() now calls the previously-dead
   ConflictService.findConflicts() against the other stored events and shows
   an "Edit" / "Save Anyway" dialog when there's an overlap.
5. ConflictCrusher no longer misses non-adjacent overlaps.
   lib/services/conflict_crusher.dart detectConflicts() now sweeps with a
   running "active events" list (tracking max end time) per day instead of
   only comparing adjacent pairs after sorting; it also now requires
   dayOfWeek to match (previously ignored day entirely).
6. Reschedule suggestions respect day-of-week.
   lib/screens/conflict_resolution_screen.dart now maps events via the
   existing EventEntity.fromClassEvent (which resolves each event's real
   next occurrence date) instead of stamping everything with "today," and
   searches free slots on the conflicting event's actual day.
7. Notification IDs are now stable, small, and collision-free.
   LocalStorageService.getNotificationBaseId()/releaseNotificationBaseId()
   hand out and persist a small counter-based ID per event (base 10000, step
   10) instead of using event.id.hashCode, which wasn't guaranteed to fit a
   32-bit int or be collision-free. notification_service.dart's schedule/
   cancel calls were updated to use it.
8. Timer leak fixed. main.dart's _ClassTimerProState now stores the 10-min
   GPS proximity Timer.periodic in a field and cancels it in a new
   dispose() override. This was causing a real "Timer is still pending"
   test failure in test/widget_test.dart, which now passes.

Implemented as stubs despite README claims:
- Focus Mode Do Not Disturb: lib/services/focus_mode_service.dart
  startSession/endSession are empty bodies (`// Future:
  flutter_dnd.setDoNotDisturb(true)`) — no real DND/app-blocking occurs.
- Location "late trigger": lib/services/location_service.dart:11-13
  hardcodes one mock campus lat/lng ("Mock Campus Coordinates (e.g.
  University of Ghana)"), not configurable per user.
- PDF import: lib/screens/import_screen.dart:132 shows "PDF support is
  coming soon!" — not implemented.
- Google Calendar two-way sync: only device_calendar (native, one-way push)
  is implemented; no Google OAuth/API integration.
- Cloud backup: settings_screen.dart:382 shows "Backup service coming
  soon."
- Matrix/OCR time parsing heuristic is fragile:
  lib/services/matrix_parser_service.dart:119-129 assumes "hour < 7 means
  PM," silently misconverting legitimate early-morning classes (e.g. a
  6:00 AM class becomes 18:00). Also assumes one fixed grid layout
  (venues as rows, time slots as columns).

Clutter / dead code:
- lib/file.dart is a leftover one-off scaffolding script (has its own
  main()) that originally generated lib/screens/home_screen.dart and other
  early skeleton files. lib/screens/home_screen.dart still exists as a
  non-functional, unrouted dead screen (Add button's onPressed is a no-op).
